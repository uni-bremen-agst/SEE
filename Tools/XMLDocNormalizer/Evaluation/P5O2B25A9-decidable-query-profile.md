## 4. Formal inputs and discovery grammar

The admission input is a FINITE, immutable, closed declaration-schema inventory:

1. Source scopes are the root and already registered finite supporting project
   scopes. Resolve owner-qualified callable DEFINITIONS once, not concrete
   instantiations. The v1 body-discovery grammar accepts ordinary, directly bound
   source method/constructor/accessor calls with finite syntactically identified
   targets and fixed signatures. Unresolved virtual/interface/delegate/dynamic,
   reflection-dependent targets, missing bodies or unmodeled implicit calls
   produce TargetClosureIncomplete, not an optimistic empty target set.
2. Every potential relevant operation is traversed, including argument/receiver
   evaluation, constructors, accessors, local sources, try/catch/finally, await/
   disposal and generated calls. A construct not covered by the finite discovery
   grammar is rejected. Existing finite trusted framework-source summaries may
   be leaves only under their actual existing contract. Documentation-only facts
   retain their separate evidence strength; they do not become Proven flow.
3. Terms in v1 are owner-qualified nominal named constructions, containing terms,
   and scoped Vars. An owner includes the existing structured assembly identity,
   module name/ordinal/MVID when supplied, declaration/arity and nested chain.
   Binder identity is (formal declaration owner, Type/Method scope, ordinal).
   A graph SLOT is additionally qualified by its callable body. Two bodies using
   Outer<T> share a formal owner but do NOT share one invocation environment.
4. Raw dynamic, tuples and other language sugar must first normalize to their
   established runtime nominal representation (tuple underlying ValueTuple;
   dynamic/Object in runtime type-argument equality; nullable annotations are not
   Nullable<T>). Unsupported/non-nominal constructors, open/unbound roots,
   function pointers, unresolved/error symbols and unproved constraint bindings
   are outside v1. Arrays/open pointer transformations are not silently included.
   This is explicit coverage loss, not an equivalence assertion on unsupported
   syntax. Both compiler adapters apply the SAME neutral grammar/normalization.
5. Each edge p->q carries a TOTAL simultaneous map for q's method and containing
   binders, expressed in p's binder scope. Sources/catches are finite terms over
   their own frame. Root binders have closed, owner-resolved ground arguments.
   Malformed arity, a foreign free Var or a missing nested owner is a certificate.
6. Existing value facts are a finite domain: ExceptionFlowValueFacts has eight
   bits, plus finite parameter/member fact sets. The discovery manifest binds
   the finite stable-member declaration universe; constructed members are
   indexed by the subsequently certified finite type environments. A new fact
   provider with unbounded keys, targets or values must fail this profile check,
   not be assumed finite. No arbitrary fact-count budget is used.

Compiler-generated default constructors are not assumed to have an empty effect:
the discovery inventory must account for the existing
AnalyzeSummaryImplicitConstructor rules, instance initializers and base targets.
An unavailable or unmodeled required effect is a coverage certificate. This keeps
the profile relative to the analyzer's explicit transfer relation; an exact
generic type projection alone cannot certify omitted constructor behavior.

Metadata/source binding receipts are real finite validation inputs, not user
claims that a missing owner is "equivalent". If the required receipt or unique
destination binding is unavailable, membership is false. Discovery may include
unreachable candidates conservatively; rejecting their growth is a coverage
false negative, not a false positive. No concrete call-context queue is drained
to discover this inventory.

## 5. IsWithinExactProfile and termination proof

For a ground primitive query: validate the closed nominal inputs/owners and the
complete finite input-set contract, then run the finite structural/base-chain
operation. Otherwise use the following full-projection test.

```text
discover finite declaration inventory without concrete graph registration
validate all terms, owners, scopes, target coverage, maps and closed root seed
if any unsupported/unknown/malformed input: OUTSIDE + certificate
make one vertex (body, formal binder) for each parameter slot
for each edge p->q and every occurrence of x in the assigned term for q.y:
    add dependency p.x -> q.y with weight = constructor depth of that occurrence
find SCCs of this finite dependency graph
if an edge of weight > 0 has both endpoints in the same SCC:
    OUTSIDE + PositiveConstructorCycle certificate
else seal the inventory/profile/root-input digest and authorize finite expansion
```

Copy edges have weight zero. A closed constant has NO incoming parameter
dependency, regardless of its own fixed depth. Count containing/nested
construction as well as ordinary argument constructors. Record ALL occurrences;
do not project coordinates independently. Weights are nonnegative. Therefore a
positive-weight dependency cycle exists iff a positive edge lies inside an SCC.
This is a finite syntactic check, NOT a query about actual infinite execution.

### Height invariant and finite state bound

Let h0 be the maximum height of closed root seeds and maximal closed subterms
of edge maps (including whole constant assignments), s the number of
slots, w the maximum constructor depth of an input map occurrence, and W the
maximum weighted path through the SCC-condensation DAG. All within-SCC edges
have weight zero. Hence W <= (s-1)*w for a nonempty graph. Along any branch of
any instantiated environment term, expansion either starts at a root/constant
or follows a dependency walk. Deleting zero-weight cycles leaves a finite DAG
path of weight at most W. By induction on edge application:

    height(environment term) <= H = h0 + W.

This bounds EVERY coordinate together, including duplicated/correlated ones;
duplication changes width, not this height invariant. The signature and arities
are finite. Let T(0)=the finite ground leaf set and
T(h+1) <= k + sum_constructor T(h)^arity. There are finitely many ground terms
of height <=H. With m maximum live slots, N bodies and F finite fact variants,
the number of concrete semantic states is at most N*F*T(H)^m. Source/catch
templates add only their fixed finite height; a validated acyclic nominal class
base chain adds a finite further amount. No newly produced source type is fed
back into an edge unless already present in its checked substitution template.

Finite exact worklist expansion therefore terminates by repeated exact states,
not by maxDepth, a timeout, an iteration count or definition-only folding.
The bound may be enormous/non-elementary in a compact description; GO is a
correctness/decidability claim, not a promise of cheap analysis. Operational
resource exhaustion must remain an explicit failed/incomplete request, never
a semantic "complete at depth N" or a forced green result.

The weighted graph can be built in O(input term occurrences); SCC admission is
O(s+dependencies), apart from canonical owner validation. The standalone harness
uses simpler O(s^3) finite reachability to cross-check the SAME condition. Its
25 finite candidate schemas are examples, not the proof of universal termination.
A5's exclusion-context cache may additionally be exponential in a finite SCC.

### Completeness of admission, not a maximal solver

True guarantees exact terminating type-query operations on the checked finite
domain. False does NOT prove divergence, undecidability or an exception escaping.
It means only that this v1 certificate does not authorize exact materialization.
An irrelevant type-transforming cycle is still rejected: no unproved liveness
or path-feasibility oracle is hidden in the test. Positive admission false
positives are correctness defects; conservative coverage false negatives are
explicitly permitted. Invalid input also deterministically returns outside
with a reason; there is no third "pending forever" outcome.

## 6. Closure, exact catch classes and concrete projection

Substitution is simultaneous and capture-free: apply(sigma,Var(x)) returns its
one supplied term without recursively applying sigma inside that replacement.
For edge p->q, sigma_pq maps q binders to p terms; a ground caller environment
rho_p yields rho_q(y)=apply(rho_p,sigma_pq(y)). For p->q->r, apply rho_p after
sigma_pq after sigma_qr. Composition is associative by structural induction,
not commutative. Containing and method binders have disjoint qualified domains.

Within ONE admitted closed inventory, finite path-map composition is safe:
a positive cycle in a graph with composed shortcut edges would expand into a
positive walk/cycle in the original dependency graph, contradicting admission.
Adding new bodies/maps/targets, joining inventories with new cross edges, or
changing a compiler/source scope invalidates the certificate and REQUIRES
rechecking before publication. Two individually safe maps are not an automatic
certificate for every graph in which they might later be combined.

Finite term normalization, substitution, union, witness selection, intersection
and difference preserve finite sets. Keep whole environments and source/edge
provenance through filtering; never take independent cartesian products of
parameter-coordinate histories. Structural equality is enough here because
individual closed nominal types are finite; arbitrary symbolic-language semantic
equivalence is NOT used in a cache key or membership test.

| Catch query class | A9 classification | Exact operation / outside reason |
|---|---|---|
| Concrete vs concrete | EXACT when both named owners/base chains resolve | Compare full construction, then correctly substituted acyclic class base chain |
| Parametric + finite closing substitution | EXACT in admitted orbit | Substitute source AND catch in their proper frames before comparison |
| Finite union of concrete types | EXACT for a complete finite incoming set | Pointwise partition; no member may vanish without definite matching |
| Restricted recursive infinite family vs concrete catch | OUTSIDE for full projection in v1 | Some Boolean masks are decidable (candidate C); that alone does not complete the requested finite output |
| Correlated family vs constructed catch | EXACT if its orbit is certified finite; otherwise OUTSIDE | Preserve tuple correlation; no claim that all correlated queries are hard |
| Catch superclass/inheritance | EXACT for resolved finite nominal class chains | Class generic arguments are invariant; an unknown base relation yields certificate |
| Nested constructed owner | EXACT with unique exact outer-to-inner reconstruction | Missing/ambiguous chain or map yields binding certificate, not name-only match |

The language premises are the official C# rules for
[constructed type identity and runtime types](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/language-specification/types)
and [substituted class bases](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/language-specification/classes).
The finite-orbit admission theorem is our analysis, not a theorem supplied by
those language-specification pages.

For each concrete witness w, P(w) is the catch relation in w's invocation frame:
caught={w|P(w)}, rest={w|not P(w)}. Their union is incoming and their intersection
is empty. Multiple catches are handled in source order; finally/handler sources
are separate local flow. A nontrivial catch filter or rethrow whose suppression
cannot be proved is NOT treated as a definite catch. Existing conservative
handler-reachability policy remains conservative; A9 does not claim to solve
arbitrary runtime reachability. An unknown relation preserves both possibilities
internally and blocks complete output, rather than deleting a possible exception.

Projection examples (after the complete graph has passed admission):

    A<T>: Fault<T>, A<int>                -> Fault<int>
    A<T>: Fault<List<T>>, A<int>          -> Fault<List<int>>
    A<T,U>: Fault<Pair<T,U>>, A<int,string>
                                           -> Fault<Pair<int,string>>
    A<T> -> A<int>, seed string          -> contexts A<string>, A<int>
    A<T> -> A<List<T>>                   -> OUTSIDE before exact expansion

The wrapped SOURCE in the second example does not feed a recursive edge and
is not grounds for rejection. All returned types retain exact owners and nested
containing arguments. One body declaration may be reused; relevant environments
M<int> and M<string> are distinct semantic states, and M<int> again reuses the
same complete state. Root+constant-closing A<string>/A<int> has three concrete
graph nodes, matching the precise old conditional permission, not A8's proposed
parameterized body-count alternative.

Type-set projection terminates exactly in this profile. Full result projection
additionally checks evidence strength, all dependencies, ownership, stable source
locations and existing path completeness. The existing MaximumPathsPerException=64
is a separate output policy: if it sets PathsTruncated, the worker must still fail
closed. It is NOT the proof of type expansion termination and cannot be used as
an implicit new generic-state cutoff. No path limit is changed by A9.

## 7. Incomplete Projection Certificate and sound conservative results

This is a semantic contract, NOT an implemented DTO. Every OUTSIDE outcome
retains these fields internally:

1. Profile/normalization version, query kind and the operation not completed.
2. Stable reason category and its finite check witness (e.g. positive edge plus
   return path in the dependency SCC), not "too hard" or an arbitrary depth.
3. Root/body/call-site, exact owner-qualified context/environment and scope/input
   digest. Invalid inputs retain their raw finite identity and validation error;
   they do not alias one universal unsupported cache entry.
4. Relevant term/map/binder/catch facts, together as a relation; no flattened
   list of independent argument possibilities.
5. Known information quality: Exact, SoundUpperBound, ProvenLowerWitnesses,
   or UncertifiedCandidates. A partial old result is not automatically an upper
   bound or a lower bound (an unknown catch can invalidate alleged escape).
6. MayMiss / MayAdd flags and their basis: Exact=false/false; a proved upper
   bound=false/possibly true; untrusted partial candidates=possibly true/true.
   "No returned result" has neither a fictitious empty exact set nor guaranteed
   candidate coverage.
7. Propagation/dependency chain and complete=false at the consumer boundary.
8. NormalFindingAdmissionBlocked=true for this request; no normal exact Finding
   may be produced from the outside result under the current policy.

| Category | Deterministic trigger | Semantic distinction |
|---|---|---|
| PositiveConstructorCycle | Positive weighted edge in a parameter SCC | Expansion not certified finite; does not prove this program diverges |
| RelationalQueryOutsideProfile | Needed query over a non-finite-orbit family, including A8's shared trace/diagonal predicate | The profile has no exact relational solver; NOT an instance-specific undecidability verdict |
| RepresentationOutsideGrammar | Unsupported term/scope/operation kind | No authorized finite nominal operation exists for this input |
| ProjectionNotCertifiedComplete | Symbolic/partial result cannot be completely projected to the required concrete facts | Includes recognized simple infinite result families, not only hard problems |
| ScopeMapNotClosed | Missing/non-total/captured binder mapping or unsupported cross-compilation substitution | The semantic input relation is unavailable, not merely a large orbit |
| OwnerBindingFailure | Zero or multiple exact owner candidates, malformed nested chain, conflicting module evidence | Include Missing/Ambiguous/Conflict details, never select the first candidate |
| TargetOrAnalysisCoverageIncomplete | Unresolved target/body, unsupported discovery construct, existing uncertainty or truncated required paths | Completeness is blocked independently of generic term decidability |

Reasons form a sorted deterministic set. Growth/correlation/projection may be
one causal chain, not three unrelated failures. Correlation in a FINITE orbit is
not a reason for uncertainty. Prototype diagnostic names PositiveConstructorCycle,
CorrelatedPredicateOutsideFiniteOrbit and its owner/map validation reasons refine
these categories; the classifier does not attempt to label arbitrary PCP instances
"decidable" or "undecidable". Certificate construction visits only finite input,
the finite dependency witness and finite already-known facts; no unfolding occurs.

### Chosen outside behavior and propagation

No conservative upper-set is exported as a successful normal result in v1.
Internally a proven overapproximation is permitted only with actual guarantee
Escaping subset U and visible precision loss. The conceptual top of the modeled
Exception universe is such an upper bound, but it is NOT a fabricated
System.Exception entry with Proven evidence. A finite known witness set L may
coexist with an unknown residual; unless the residual is proved empty, L is not
a complete result. Unknown transfer/catch decisions cannot suppress possibilities.

At joins, completeness is the conjunction of dependency completeness; reason
sets and affected contexts propagate. Exact outputs cannot cleanse an incomplete
dependency, nor may a cache hit do so. Definite catch-all can discharge an unknown
incoming type-flow obligation only when the grammar proves that *entire* protected
flow is covered and handler/filter/finally effects are accounted for. v1 does not
use this as a shortcut to expand an otherwise uncertified target graph: such a
request may conservatively remain outside. No hidden third state is necessary.

The existing DTO string UncertainTargets and canonical AnalysisUnsupported can
express blocking presence/display text, but cannot encode all certificate fields
or distinguish upper/lower/uncertified result sets. A later implementation needs
a neutral INTERNAL classified outcome wrapper, shared by both analyzers. It must
not rely on every old consumer inspecting a legacy display string correctly.

## 8. Existing Finding policy and minimal wire decision

HistoricalAnalysis lines 74--80 rejects nonempty uncertainties or truncated
paths. HistoricalWorkerResponseValidation lines 62--98 requires a genuine failed
envelope with no Result/Provenance/policy/documentation/FindingDirect, and rejects
incomplete success again. Finding receipts additionally require independent
complete Direct and documentation evidence. DeclaredExceptionFindingPolicy
accepts only original successfully validated policy-call receipts; canonical
validation requires Proven flow entries, not arbitrary possible candidates.

Consequently future policy preparation is:

| Result quality | Potential later B25B use | Decision under unchanged policy |
|---|---|---|
| Exact type query + complete validated request | Necessary, not sufficient | Still requires mode, scope, ownership, documentation and original validation receipts; no activation now |
| Sound conservative upper bound | Only a separately approved visible possible-exception Finding semantics could consume it | NOT accepted as normal Proven/exact output |
| Incomplete/uncertified | No normal exact Finding | Whole request fails closed; no partial Direct fallback |

**Wire decision: no new result/family/certificate DTO and no protocol extension
for this follow-up.** Keep full certificate internally; transmit the existing
failure envelope: Success=false, Result=null, Failure.Code=UnsupportedContext,
Message plus deterministic version-neutral Details (profile/reason/context digest
and diagnostic text). All success-only payloads remain null. Main already receives
failure and therefore cannot mint a Finding receipt. It needs that failure status,
not a full executable symbolic family. Current must produce the same classified
fail-closed analysis outcome. Existing AnalysisFailure for other old failures is
unchanged; these new profile rejections have an explicit semantic reason.

No Roslyn symbol crosses the boundary. No Current/Historical routing, compiler
version or isolation contract changes. A future UI that wants machine-readable
certificate fields beyond existing Details would be a separate wire decision,
not a reason to add a speculative transport model now.

## 9. Cross-project / cross-compilation contract

A->B resolves B by its exact structured assembly/module/declaration and containing
chain, then maps ALL B binders to A terms. A->B->C composes those maps; it does not
normalize every callable to an uninstantiated definition. Example: A passes
(int,string) to B.P<T,U>; B calls C.Q<List<T>,U>; C's Fault<Pair<X,Y>> projects
to the exact C-owned Fault<Pair<List<int>,string>>. The two compiler object graphs
may differ; the neutral owner/binder/map comparison is the same.

Resolve a nested type outer-to-inner: uniquely resolve outer declaration in the
verified destination owner, construct it with its own arguments, enumerate exact
nested metadata name/arity on that constructed container, construct its OWN
arguments, then uniquely resolve/construct the method with separate method args.
Recompute and compare the full canonical identity to the requested one. Zero or
multiple matches, changed owner/arity, missing arguments or a non-total map is
OUTSIDE. Lookup by declaration ID may enumerate candidates; it may NEVER select
the first same-named type as the semantic answer.

Module handling is explicit: CanonicalModuleIdentity carries optional MVID, but
the current factory supplies null. A null MVID is not an invented equivalence to
every emitted module. Use exact existing module/source scope identities; if a
source/PE alias is required, demand the existing validated source/binary
correspondence as a finite trusted mapping and retain its fingerprint. Missing
correspondence is OwnerBindingFailure/ScopeMapNotClosed. No new compiler-provenance
layer is authorized by A9, and two matching display names are not that receipt.

Rebinding preserves constructor structure, so it preserves the weighted graph
up to verified owner renaming. Any changed map/signature/target set invalidates
admission and is checked again. Compiler-local exactness may therefore become
outside at rebinding, with a certificate, rather than a silently partial result.
Current and Historical must share the neutral profile/checker/reason ordering;
backend capabilities can reject an operation, not change exact into unmarked
conservative semantics for the same supported neutral query.
The v1 supported syntax/capability grammar is a SHARED whitelist, not selected
according to the backend: operations requiring unavailable Historical semantic
facts are outside this new profile for both adapters. Inability to reconstruct
an otherwise specified input is an explicit input-projection failure, not a
backend-specific conservative answer. Equal validated canonical inputs must give
identical classification, reasons and projected types in both processes.

## 10. Lifecycle and A5 integration

Actual order today: TryBuildTransitiveSummaryGraph registers root, then
BuildPendingSummaryNodes drains DequeuePendingOrDefault; target registrars invoke
graph.GetOrAdd on calls. Only afterward does the evaluator find A5 SCCs. Even a
try-fragment later suppressed by SuppressAll can have registered a target during
traversal. Neither result-time validation nor catching an exception after the
queue starts is a termination safeguard.

Required future order:

    bind root/scope -> discovery-only finite definition prepass
    -> validate/close templates -> IsWithinExactProfile
       OUTSIDE: certificate, no constructed target registration
       EXACT: seal profile/input digest -> concrete GetOrAdd/Pending Queue
              -> finite graph frozen -> existing A5 SCC/evaluation
              -> complete exact projection or explicit incomplete outcome

The prepass cannot call existing side-effecting registration and pretend it has
not expanded anything. It needs a discovery-only target sink/capability, keyed by
definitions and finite syntactic facts. Each definition is inspected once (or
finite declared fact variants); no concrete type instance is recursively analyzed
there. The barrier is at session entry, before constructed root/target queue
publication; registrar guards additionally reject unsealed/new schema data.

The weighted parameter SCC is a static termination certificate, not a second
summary recursion engine. AFTER finite materialization, A5's actual semantic-state
SCCs, ancestor exclusion, completed-only cache and per-root isolation remain
binding. A recurrence to a definition with a changed environment is not an active
key revisit. Do not fold it, and do not cache its partial result unrestrictedly.

Cache keys bind profile/normalization version, finite inventory/scope/owner
fingerprints, exact root environment, relevant value facts and query kind.
Completed result reuse retains A5's (semantic key, excluded SCC ancestors).
Profile/certificate caches cannot satisfy a complete-result lookup; an empty
partial result does not become an exact empty result. Any discovered new target
or map invalidates the seal before concrete publication. This prevents late
incremental schema discovery from resurrecting A6's unbounded queue.
