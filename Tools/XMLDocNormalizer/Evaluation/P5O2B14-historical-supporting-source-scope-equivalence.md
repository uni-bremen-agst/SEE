## Four-mode decision before implementation

Direct binds using every tree in the target compilation but traverses only the
root. ProjectTransitive uses the summary engine; project membership comes from
reporting-compilation ownership, not a filename directory. SolutionTransitive
adds recursive ProjectReference closure and registered supporting scopes.
ProjectTransitiveDeclaredExceptions is **not XML contract traversal**: actual
detector code guards on locally declared exception types and filters reporting
relevance. The B13 description was too coarse here. XML providers and Historical
Finding import remain excluded, so this mode must remain explicitly unsupported
at the canonical worker boundary until its detector-policy contract is designed.

The connected B14 slice is complete bounded **same-project sources**, explicit
assembly membership and Direct/ProjectTransitive local reachability. Existing
SolutionTransitive requests remain supported only for their stated local graph;
an explicit single-project profile can prove this same local scope, not arbitrary
solution closure. Cross-project dependencies/supporting registries are B15.
No Workspace objects, MSBuild loading, engine selection or analyzer changes.
